# Нагрузка клиента: изменения и измерения

11 ноября 2026. Цель — не выполнять лишнюю работу в простое и уменьшить нагрузку интерфейса.

## Изменения

- Убран автоматический запуск диагностики CIM/PowerShell при открытии приложения. Она запускается один раз при первом открытии «Диагностики», повторно — кнопкой. Проверка журнала отката при старте сохранена.
- Полностраничная анимация отключена в поставляемой конфигурации (`animation_duration_ms: 0`); при нулевой длительности эффект прозрачности не включается.
- У кнопок удалены индивидуальные анимации и дополнительная отрисовка полупрозрачного слоя. Hover/focus/pressed остаются штатными стилями Qt.
- Прогресс обновляется непосредственно по событиям рабочего потока без анимации между значениями.
- Кольцо состояния не запрашивает перерисовку, если счётчики не изменились.
- QR-библиотека загружается только при создании QR, HTTP/TLS-клиент — при первом запросе API. Проверка PRO перед применением сохранена, сеть не обходится.

Постоянных таймеров мониторинга оборудования и автоматических FPS-тестов нет. Polling входа существует только в открытом диалоге Telegram и ограничен сроком сессии. Диагностика и тесты по явному запросу всё ещё требуют ресурсов; PresentMon не работает постоянно.

## Контрольный замер

Команда из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/profile_performance.py --output runtime/performance-after.json
```

Инструмент создаёт отдельную папку данных внутри runtime, запускает настоящий Qt-интерфейс,
не применяет твики, не входит в Telegram и не использует ваш сохранённый токен. Чтение журнала
и диагностики исходной версии — только чтение системных данных. Созданная временная папка
удаляется при нормальном завершении. Qt работает в offscreen-режиме по умолчанию.

| Показатель | До | После |
|---|---:|---:|
| Автоматические запуски диагностики при старте | 1 | 0 |
| Время до завершения стартовых задач, секунды | 0,886 | 0,480 |
| Рабочая память в простое, МиБ | 80,13 | 72,94 |
| Частная память в простое, МиБ | 48,12 | 42,14 |
| CPU-время 27 переходов, секунды | 0,6562 | 0,1250 |
| События отрисовки за 27 переходов | 10 629 | 852 |
| CPU-время 10 секунд простоя | 0 | 0,0156 |
| CPU-время 10 секунд в свёрнутом состоянии | 0 | 0 |

Исходные JSON: runtime/performance-before.json и runtime/performance-after.json.
Это отдельные локальные прогоны, не статистическое исследование. Во время финального прогона
также выполнялись автотесты; значения CPU/времени зависят от планировщика и фоновой нагрузки.
Число событий включает дочерние Qt-виджеты, это не количество экранных кадров.
0 секунд означает отсутствие измеримого CPU-времени при точности системного счётчика,
а не физическое отсутствие любой работы. Результаты относятся к процессу Python/Qt,
не учитывают CPU дочернего PowerShell, GPU-композитинг, производительность CS2 и отличия EXE.

Память заметно вырастет после первого использования сетевых функций, QR или больших отчётов:
отложенная загрузка не удаляет функциональность и не гарантирует неизменные 73 МиБ всю сессию.
Отсутствие постоянной нагрузки нельзя заменять периодической очисткой working set или GC по таймеру:
такие трюки и изменение системных приоритетов не добавлялись.

Проверка регрессий: **243 passed**, одно прежнее предупреждение Starlette/AnyIO.
Добавлены сценарии отсутствия стартовой диагностики, однократного запроса при входе в раздел,
ручного повторного замера и обновления прогресса без запуска декоративных анимаций.

Отдельная сборка: `dist/performance-2026-11-11/ShatliFlux/ShatliFlux.exe`.
PyInstaller завершился успешно; EXE прошёл проверку старта в offscreen-режиме
с отдельным APPDATA. Сборка проверочная, не подписана и сохраняет локальный адрес API.
Для переноса необходима вся папка ShatliFlux вместе с `_internal`.

## Что ещё измерить перед продажей

На реальном видимом и свёрнутом EXE: 5 минут простоя, 100/150/200 % DPI, диагностика,
вход и повторные переходы, запуск/отмена PresentMon. Снимать CPU и память дерева процессов,
GPU и изменение памяти после нескольких одинаковых циклов; не сравнивать только диспетчер задач
в случайный момент. Провести несколько CS2-прогонов с закрытым и свёрнутым клиентом.
Это входит в RELEASE_OWNER_PLAN.md и пока не подтверждено текущим offscreen-замером.
