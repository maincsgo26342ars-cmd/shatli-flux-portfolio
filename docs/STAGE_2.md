# Этап 2: система и восстановление

Версия 0.2.0 добавляет чтение реальных сведений ПК и запуск восстановления Windows. Вкладки стали контрастнее: плотный тёмно-зелёный фон, выраженная граница, полная мятная заливка активной кнопки.

## Файлы и запуск

- **`app/core/system_info.py`, `app/core/scripts/system_info.ps1`:** CPU, все найденные GPU, объём памяти, название и сборка Windows через локальный CIM.
- **`app/core/windows.py`:** проверки платформы, запуск команд без shell, явное разовое повышение прав.
- **`app/core/restore.py`, `app/core/scripts/create_restore_point.ps1`:** создание и проверка точки, запуск `rstrui.exe`.
- **`app/ui/jobs.py`:** фоновые задачи без зависания интерфейса.
- **`app/ui/pages.py`, `window.py`, `theme.qss`:** кнопки, сведения о ПК и усиленная навигация.
- **`tests/test_stage2.py`:** проверки чтения, ошибок, отмены UAC и неподтверждённого результата.

Запуск из корня `shatli_flux` в обычном PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m app.main
```

Запрос UAC возникает только после подтверждения «Создать». Команда `Checkpoint-Computer` предназначена для клиентских Windows и не позволяет создавать более одной точки за сутки; программа это ограничение не обходит ([Microsoft Learn](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/checkpoint-computer?view=powershell-5.1)).

После вызова скрипт проверяет наличие точки с уникальным описанием и сообщает успех только при подтверждении. Он не включает защиту системы самостоятельно, не меняет ExecutionPolicy и не запускается скрыто.

Уточнение в версии 0.3.0: содержимое фиксированных открытых `.ps1` передаётся PowerShell через `-Command`, без `-ExecutionPolicy Bypass` и без закодированных команд. Это позволяет не требовать от пользователя изменения политики для запуска локальных файлов скриптов; блокировку самого PowerShell или CIM программа не обходит.

## Проверка

Автоматические тесты изолируют системные вызовы, поэтому их успешность не заменяет проверку настоящей Windows. В Linux доступен только просмотр интерфейса, без подставных характеристик ПК.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

- [ ] Windows 10 и Windows 11: обычный запуск не вызывает UAC.
- [ ] CPU/GPU/RAM/Windows совпадают с системными сведениями; полные строки доступны в подсказках чипов.
- [ ] При отсутствии данных показано «Не определено», не вымышленное устройство.
- [ ] «Создать»: отказ в первом подтверждении ничего не запускает.
- [ ] Отмена UAC не показывает успех.
- [ ] При включённой защите и отсутствии ограничения времени точка появляется в Windows.
- [ ] При выключенной защите или ограничении 24 часов нет ложного успеха.
- [ ] Мастер восстановления открывается; сам откат Windows пользователь выбирает уже в мастере.
- [ ] Во время операции вкладки работают; закрытие просит дождаться завершения.
- [ ] На 960×640 и масштабах 100/125/150% кнопки навигации читаются.
